# OpenAI image SendMessage reference-guard removal — proposed execution

**Function:** F-INTEL-OPENAI-IMAGE-REFERENCE-REMOVE-01. **Purpose:** future execution of the user's narrowed correction to the accepted direct OpenAI image `SendMessage` pilot. This document is proposed action, not implementation or behavioral acceptance. The earlier offline PASS remains attached to its exact historical snapshot.

## Current state and boundary

The [OpenAI module](../Src/Intelligence/OpenAI/PowerShell/Intelligence_OpenAI.psm1) routes v2 image `Config.Profile.Key` to the registered profile, route and resource, checks `Prompt.model` against the registered model, then forwards native `Config.Prompt` JSON to REST. The edit-specific block beginning `if ($kind -ceq 'OpenAIImageEdit')` currently inspects `images` reference shape and restricts `image_url` and `file_id`. The user's current direction moves that provider-specific responsibility out of the adapter now. The [ST image child](../../BDDB.Infrastructure/integration/sovereign-trust/content/test/plans/st-test-adapters-intelligence-image.json) only loads the BFL formatter and has no OpenAI send call. No caller-side OpenAI validation plan will be created, loaded or invoked in this change. A future caller may load and `InvokePhase` an external validator before `SendMessage`; that is a separate proposal, and no current ST image-output correctness is inferred.

The adapter still pins the registered OpenAI endpoint and credentials, but it no longer certifies provider edit references. The future external ST validation plan is optional to this correction and has no ghost load, phase, fixture or file now.
