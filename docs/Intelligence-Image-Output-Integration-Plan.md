# Intelligence image-output integration plan

## Purpose and present boundary

Implement the same selected Sovereign Trust image-output sequence for **four** producers: `OpenAI`, `FoundryOpenAI`, `CodexCLI` (the user's “contextcli”), and `FoundryBFL`. For each, generate a simple black line drawing of a squirrel on a plain white background, classify it from `CAR`, `SQUIRREL`, `TREE`, edit that producer's squirrel into a tree, and classify the edit as `TREE`. Both vision checks use the one accepted `FoundryOpenAI` Responses `Vision` evaluator and supply an explicit text question plus that producer's generated image. Capture five producer-qualified native Boolean leaves (generation materialization, squirrel classification, edit materialization, tree classification, cleanup); false or absent leaves fail the selected campaign. Producer identity stays on every request, result key, blob and local file.

This is a future execution plan, not evidence of implemented image activity or provider behavior. The currently loaded [mapped Intelligence source](../../SovereignTrust.Foundation/Src/PowerShell/Classes/Adapters/MappedIntelligenceAdapter.ps1) allows `SendMessage`, `SendMessageOriginal`, and `HandleMessage`; it does not allow `GenerateImage`. Current AzureFoundry, native OpenAI and CodexCLI adapters have different request/response transports and none has an accepted four-producer image-output contract. The [multi-provider plan](./Intelligence-AzureFoundry-MultiProvider-Plan.md) proposes BFL `ResolvePromptProfile`, `GenerateImage`, a v2 jacket and versioned image result for the Foundry route; it does not establish the other three producer routes. Formatter FF-01/FF-04/FF-05 are still blocked in the existing Adapters Working record. No live run or image-output claim is permitted until each selected producer's dependency is accepted.

- After prerequisite acceptance for all four routes, run one bounded selected serial live campaign only with producer-qualified isolated blob prefixes, exact model deployments/secret scopes, CLI artifact workspace, budget and cleanup available. Freeze config/plan/formatter/fixture/source identities, each actual producer model/route and the shared run ID; capture per-producer generated image result metadata, local/blob SHA-256 and MIME, common evaluator text+media request identity, selected JSON values, failed/skipped phases and cleanup receipts. Avoid raw image/credential logging. Run the focused Foundation/Adapters/CodexCLI output tests for their accepted implementations before live selection and affected regressions after changes. No full-suite substitution.
- Model output is variable. Do not use exact pixel equality or claim a fixed squirrel silhouette. The discriminating live oracle is a valid persisted image plus a separately routed text-and-image vision response choosing `SQUIRREL`, followed by edit image plus independent choice `TREE`. One incorrect classification is a failed run, not a reason to silently regenerate until green. A retry, seed, alternate model or prompt change is a new recorded attempt with its own identity and reviewed boundary; retain adverse receipts. A mock proves orchestration, not image semantics. The single live campaign proves only that observed instance, not a statistical success rate.
- Stop dependent work when any selected producer lacks a unique supported slot, compatible v2/profile parser, output/edit activity, accepted result shape or safe materialization; when the common FoundryOpenAI vision evaluator cannot resolve independently; when BFL formatter FF findings remain open; when per-producer URL/base64/local-artifact safety or six-resource cleanup and failure recovery is unproven; or when live deployment/secret/CLI budget is absent.
